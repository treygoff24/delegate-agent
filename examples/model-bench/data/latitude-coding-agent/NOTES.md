# Latitude Coding-Agent Benchmark data notes

- **What it measures:** A common four-tool coding-agent loop fixes planted bugs in small JavaScript projects. The harness scores whether pristine tests pass, records run cost and latency, tool-call errors, and test-file tampering. Results also include hidden-test (blind) runs.
- **Captured source/version:** `results/results.jsonl`, 847 per-run records at repository commit `f93b5a8ea5cdb42ccd208339dce48c2b23af935f`. The latest record is dated **2026-07-29**; the results file's latest commit is 2026-08-04. Captured 2026-09-23 UTC from the GitHub API/raw file. The source's result directory index, latest commit metadata, report code, model definitions, README, article, effort cutoff, blind-task token metadata, pilot data, and license are retained in `raw/latitude-coding-agent/`.
- **How collected:** Downloaded the final raw JSONL from GitHub and inspected `src/report.ts`, `src/models.ts`, the README, article, and LICENSE at the source repository. No rendered leaderboard scraping was needed. The separate `pilot.jsonl` was not merged into final results. All `status: ok` records in `results.jsonl` were included, matching the source report's input filter.
- **Coverage and row count:** 10 model names, 14 distinct model/effort configurations, 37 configuration-by-tier combinations, and 259 rows (7 metrics per combination). The report tiers are `easy`, `hard`, and `blind`; each of five Claude Opus 5 effort settings has hard and blind results only, so no easy rows exist for those settings. Kimi K3 has just one easy run. The source includes five explicit Opus effort levels (`low`, `medium`, `high`, `xhigh`, `max`); other records have no stated effort. No Gemini runs appear in the current results, despite Gemini being listed in the model definitions.
- **Metrics:** `solve_rate` follows `report.ts`: successful attempted runs divided by attempted runs, rounded to a whole percent. The same row carries the report's cost per solved task (total run cost divided by successful runs, rounded to $0.001) and median wall time in seconds (rounded to 0.1 s). `total_cost` is summed over all runs including content-filter refusals and rounded to $0.01. `median_steps` is the median of attempted runs rounded to an integer. `tool_error_rate` is (tool errors + malformed calls) / tool calls, rounded to 0.1 percentage point. `tampered_runs` counts attempted runs flagged for test-file tampering. `refused_runs` counts runs whose finish reason is `content-filter`, matching the report's refusal handling. The source report does not aggregate first-action latency; `median_first_action_latency` is a separate median computed from raw `firstActionMs` values for attempted runs, converted to seconds and rounded to 0.1 s. For rate rows, `n` is the attempted-run denominator; for tool error rate it is the number of tool calls; counts use their corresponding run denominator.
- **Caveats:** The source describes this as a small, independent benchmark and reports costs priced from models.dev rates; published runs used default settings except for the later Opus effort sweep. The article discloses that Claude-based agents built the harness and authored tasks, and that family bias cannot be ruled out. Tasks are tiny libraries with planted bugs and are not representative of repo-scale work or ambiguous requirements. The data are stale relative to the requested capture date (last record July 29, 2026). Aggregates here follow the checked-in report script where available; the first-action median is computed from raw runs rather than a published table. Cost values and outcomes are benchmark-owner reported and were not independently reproduced.
- **License/redistribution:** The source repository includes an MIT license, preserved as `raw/latitude-coding-agent/LICENSE`.
- **Not captured:** Private Latitude traces are not included; the public JSONL contains trace identifiers only. No confidence intervals are reported. The public source does not state a specific benchmark release/version beyond the repository commit captured here.
