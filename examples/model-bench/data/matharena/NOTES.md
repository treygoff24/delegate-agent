# MathArena collection notes

- **What it measures:** MathArena evaluates language models on recent mathematics competitions and research-math sets. It publishes one leaderboard per competition and an IRT-based expected-performance overview across non-deprecated competitions.
- **Data captured:** 2026-09-22 (local collection date; raw files carry the exact UTC retrieval timestamp). This is a live snapshot, not a named benchmark release. MathArena's model overview shows individual evaluation dates; the per-competition table does not expose a single snapshot/evaluation date for each score, so `measured_on` is null where unavailable.
- **Coverage:** the capture includes the model overview and all nine competition views not marked deprecated on the homepage at collection time: ArXivLean June 2026; BrokenArXiv overall, May, June, and August 2026; and ArXivMath overall, May, June, and August 2026. The homepage and exact JSON responses from `/competition_tables/<id>` are saved under `raw/matharena/`; `capture-index.json` lists the URLs. The models overview HTML is saved as `models-page-1.html`.
- **Row count:** 648 rows: 104 numeric configurations in the expected-performance overview (one score row each), plus 137 numeric per-competition configurations (one accuracy row each, with reported cost and time paired on that row) and their available output-token, input-token, and average-retry metrics. Auxiliary values are separate rows as required by the shared format. Some tables omit time or an auxiliary value, so the count is smaller than four rows per scored competition configuration. The tables also list unscored `N/A` configurations; these are omitted because the schema requires a numeric `value`. There are 127 distinct verbatim model labels across subsets; effort variants remain distinct configurations.
- **Metric definitions:** `expected_performance` is the site's mean predicted normalized question score from its two-parameter item-response-theory model, expressed as percent. `accuracy` is the displayed competition result in percent. `ci` copies the displayed 95% score interval half-width, also in percentage points. Per-competition `cost_usd` is the displayed cost for one model run on one problem (`per_task`); `time_s` is the displayed average answer time converted from minutes/seconds to seconds (`per_task`). The overview cost is expected cost per problem. Output/input tokens and average retries are copied as independent descriptive metrics. Counts and times are copied without estimating missing values.
- **Caveats:** results are published by the independent MathArena authors. The site marks some model results with a warning when the model postdates the competition release; those entries retain the warning in `model_raw` and have a contamination caveat in `notes`. The authors design new problems to reduce training contamination, but the site's own warning shows this cannot be assumed absent. No per-model sample count was exposed in the captured tables. Expected-performance estimates and individual competition scores measure different things and should not be conflated. A dash, invalid cost, or `N/A` is not converted into a number.
- **License/redistribution:** the linked evaluation-code repository identifies its code license as MIT. The leaderboard pages and captured results did not state a separate data license or redistribution grant; row-level `license` fields are therefore null. Repository code licensing should not be assumed to license leaderboard data.
- **Collection method:** fetched the homepage and `/models?page=1&q=` directly, then read the page's own `/competition_tables/<id>` JSON endpoint for each active view. Each endpoint returns HTML strings containing the problem table and summary leaderboard; this collection uses the summary leaderboard. Raw responses are preserved for verification.
- **Not captured:** deprecated competition views, problem-level answer cells/raw model traces, detail pages beyond their rows as linked from the overview, or unscored `N/A` rows (no numeric result to encode). The public model overview and current active competition tables are included.

## Verification

- Parsed all 648 JSONL lines; every line is valid JSON and contains all fields listed in `examples/model-bench/SCHEMA.md`. The file contains 127 distinct `model_raw` labels.
- Spot-checked 10 score rows against the saved source captures: the three highest expected-performance scores; all eight model configurations dated within the month before 2026-09-22 (the three highest overlap these); and the two highest scores in ArxivMath August. The checked values, confidence intervals, and paired costs matched. No live-source fallback was needed.
- Coverage check: the captured models overview lists 122 configurations, with 104 numeric expected-performance values. All 104 are present exactly once as `expected_performance` rows; the other 18 have no numeric score. Across the nine active competition captures, all 137 numeric accuracy entries are represented, with no missing or extra accuracy rows.
- Changes: none; no provable row errors or omissions were found.
