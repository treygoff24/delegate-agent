# Scout note — public model benchmarks (2026-09-22)

The useful landscape is a portfolio, not one universal rank. For repository coding, prioritize fresh SWE-rebench tasks and long-horizon FrontierSWE, then add SWE-bench Pro and Terminal-Bench 4.0. TerminalWorld and TUA-Bench broaden terminal work beyond curated coding tasks. For general coding, retain LiveCodeBench and Aider; ProgramBench and CodeClash test building software from scratch or goal-oriented development. For web/UI, pair WebDev Arena / Code Arena crowd preference with executable browser or computer-use tasks (WebArena, WebVoyager, OSWorld 2.0) and screenshot-to-code (Design2Code, UIBenchKit). Crowd Elo measures preference; task pass rates measure completion. The checked WebDev Arena publication says its leaderboard description was last edited June 2025; treat freshness separately from ongoing votes.

For economically valuable work, APEX-1 spans consulting, investment banking, big law, and primary care; GDPval uses expert comparisons on occupational deliverables. Both are valuable broad knowledge-work sources but are provider-run (Mercor and OpenAI respectively), and neither publishes the full task-level cost/time fields needed for a clean Pareto analysis in its current leaderboard. APEX-SWE adds applied software integration and observability. Legal coverage is thinner: Vals-run LegalBench and LEXam are useful alongside occupational legal slices, but do not establish safe legal advice or jurisdiction-specific competence. Finance coverage is also thinner and fixed-task sets dominate; FinanceBenchmark is a secondary composite, so prefer FinanceBench / FinQA underlying records where comparable and add finance-agent evaluations when harness and data are disclosed.

The strongest directly observed quality-plus-cost/time options are FrontierSWE V2 (success score, per-trial cost and wall time, task-level traces), SWE-rebench (resolved rate and cost per problem), BFCL V4 (accuracy, estimated total benchmark cost, latency), Terminal-Bench 4.0 (resolution rate, cost and tokens), and TerminalWorld (score and cost/cost per pass). GDPval additionally compares quality with inference cost and elapsed time in its research reporting. Artificial Analysis Search API Index reports agent-task quality with provider cost and end-to-end time; it measures the search-service stack. OSWorld 2.0 includes costs in some visible rows, but cost coverage should be checked before treating it as a full frontier. Latitude Coding-Agent Benchmark adds solved-per-task cost and wall-clock latency with raw run JSONL; RealDataAgentBench reports score and average task cost for data-analysis workflows. These join the first collection lanes for a quality/cost/time Pareto view; keep denominators, effort, provider price basis, cache treatment, and harness with every row. Most boards still omit wall time or per-task cost.

For reasoning/math/science, collect LiveBench (rolling), HLE, GPQA Diamond, MMLU-Pro, MathArena, and SciCode. SciCode is especially relevant to scientific coding, but its recent verified-revision work identifies benchmark defects: retain exact version and uncertainty. For tool use, BFCL V4 tests function calling, τ-bench tests multi-turn policy-bound tool work, Toolathlon adds long-horizon app/tool tasks, and OSWorld 2.0 tests computer use. For long context, AA-LCR is the clearest current cross-model board found; it tests synthesis across roughly 100k tokens, not maximum context capacity. Artificial Analysis is a useful independently measured aggregate and source of latency, throughput, and price, but preserve its index version and component scores. LMArena supplies broad human preference. IFEval/IFBench add explicit instruction following.

Coverage gaps: white-collar, legal, and finance have few open, independently rerunnable end-to-end leaderboards; RealDataAgentBench is a useful but narrow data-science exception; many scores there are evaluator- or provider-reported. UI/frontend has abundant preference voting but relatively little current, standardized functional evaluation. Serving data is richer for tokens/sec, latency, and posted prices than for total workload cost. Recent model names explicitly present on the current FrontierSWE and APEX pages include GPT-6 Astra, GPT-5.6, Claude Fable 5.1, Claude Opus 5.5, Gemini 3.8 Flash, GLM-5.3, Grok 4.7, Kimi K3, Qwen3.8-Max, DeepSeek V4 Flash Vision Exp, and Muse Spark 1.2/1.3. AA-LCR also exposes Step 5 Preview. Treat these as incoming labels, not canonical IDs; collector lanes should preserve exact source spelling and reasoning-effort suffix, then reconcile against `models.json`.

Stale entries are included only for commonly cited baselines (SWE-bench Verified, Design2Code, WebVoyager, FinanceBench, FinQA). Marked stale in the manifest; scores are not comparable across changed tasks, harnesses, and prompts. Collection gaps this run: the SWE-rebench leaderboard body exceeded the browser extraction limit (its searchable page and dataset were reachable); the Arena root and UIBenchKit pages yielded no extractable page text, and some leaderboard tables render dynamically. Several official entries expose no standalone downloadable score table, so `data_url` is null where I could not verify a raw-data source.
