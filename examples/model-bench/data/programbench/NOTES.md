# ProgramBench collection notes

- **What it measures:** Agents receive an executable and its documentation, then build a complete implementation from scratch. ProgramBench compares the implementation with hidden behavioral tests across 200 tasks. The official site says the agent cannot access source code or the internet, cannot decompile the executable, and must choose the implementation language and architecture.
- **Captured release/date:** Official leaderboard snapshot updated **2026-09-09**; both leaderboard pages report 200 tasks. Captured 2026-09-22 (retrieval timestamp in each row is UTC).
- **Collection method:** Direct `curl` captured the official homepage and `/extended/` HTML; the GitHub API request returned HTTP 403. Firecrawl also scraped the two official pages; the extracted page text is preserved in `raw/programbench/leaderboard.md` and `raw/programbench/extended-results.md`. The homepage's chart lists average test pass rate and a score/cost; the extended table lists resolved and almost-resolved rates, average per-task API cost, and average LLM calls per task. Scores and names were transcribed from these snapshots.
- **Rows/count:** 21 published model configurations × 5 reported metrics = 105 rows: `resolved_rate`, `almost_resolved_rate`, `avg_test_pass_rate`, `calls_per_task`, and `tokens_per_task`. The cost is attached to the three score rows rather than repeated as its own metric, following the shared schema's paired-cost rule. The homepage average-pass-rate row uses its paired chart cost; resolved/almost rows use their paired extended-table cost. There is no time result in these pages. `n=200` records the published number of task instances, not an independently verified per-metric sample count. `measured_on` uses each run date embedded in the official chart metadata.
- **Metric definitions:** `resolved_rate` is the percentage of tasks fully solved according to hidden behavioral tests. `almost_resolved_rate` is the percentage of tasks where at least 95% of tests pass. `avg_test_pass_rate` is the percentage shown as the homepage chart's score and is the mean test pass rate across task instances. `calls_per_task` is the extended table's average LLM calls per task. `tokens_per_task` is the chart metadata's average token count per task. Costs are USD average API cost per task (`per_task`). Values are copied as displayed, with `%` kept as the unit.
- **Cost discrepancy:** The homepage score/cost chart and extended table differ slightly for some configurations (for example, Claude Opus 5 (xhigh): $50.53 on the chart vs. $51.04 in the extended table; GPT-5.6 Sol: $1.00 vs. $1.02). Resolved/almost rows use the extended table costs; average-pass-rate rows use the homepage chart costs. The source does not explain the discrepancy. The chart metadata also shows slightly different average call counts from the extended table for some configurations; `calls_per_task` uses the extended table values.
- **Harness/reporting:** All listed rows name `mini-SWE-agent`. This is an independent benchmark team's reported result; per-configuration evaluation details and confidence intervals are not published in the captured tables. The 200 tasks are drawn from open-source projects, so training-data exposure is possible; ProgramBench's site acknowledges this and says it monitors memorization and reports a different-language ablation in its paper. That is the authors' assessment, not independent verification.
- **License/redistribution:** The GitHub repository describes the ProgramBench software as MIT licensed, but the leaderboard pages do not state a separate license for the result data. The website links Meta's Terms of Use. No explicit data redistribution grant was found; row `license` is therefore null.
- **Not captured:** The dynamic chart's task-by-task distributions, detailed run pages, and any confidence intervals were not included; the task-by-task distribution chart data and detailed run pages were not captured; no separate raw machine-readable results endpoint was located. The leaderboard says it was updated September 9, 2026, so the captured snapshot may become stale after that date.
