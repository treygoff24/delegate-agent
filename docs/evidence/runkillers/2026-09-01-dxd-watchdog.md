# dlg-dxd watchdog diagnosis at c8fcab6

## Root cause

The confirmed field false-positive was an observation failure, not a dead supervisor: the old strict reader could open an inode just before atomic replacement, see the now-unlinked inode, return no payload, and let the watchdog interpret that transient as dead state (`bd show dlg-gia`). `dlg-dzz` fixed that specific race with a bounded reopen at `f9b7190`, and `dlg-a2w` fixed the separate journal-silence theory with a timer-driven lease at `702c5ba`. At current HEAD, the remaining family has two mechanisms: `_check` still collapses read failures into `state_missing` or `heartbeat_invalid`, and `_run` still cancels on one `heartbeat_stale` sample. A healthy current supervisor therefore does not go stale merely because merge validation or close snapshotting writes no journal rows; it goes stale only when the timer cannot successfully publish for more than the window, Python threads are not scheduled, wall time jumps, or the file is externally regressed. The old runs did not record the trigger reason, so their individual deaths cannot be reclassified after the fact (`bd show dlg-9za`).

## Conditions that can make the current lease stale

The watchdog's definition of stale is a valid on-disk `heartbeatEpoch` more than `stale_seconds` behind `time.time()` (`runtime.py:4341-4350`). At the 5-second default, a healthy main workflow can meet that predicate under these conditions:

1. **The timer thread is not scheduled for more than five seconds.** `SIGSTOP`, cgroup or VM suspension, host sleep, severe scheduler starvation, or a native extension holding the GIL can do this. After scheduling resumes, the timer and watchdog race; the watchdog currently needs only one stale sample. Ordinary pure-Python CPU work is not enough under the live interpreter's normal 5 ms switch interval (`python3 -` printed `switch_interval=0.005`), although code that raises the switch interval can recreate starvation. A subprocess wait, normal filesystem syscall, or ordinary merge subprocess normally releases the GIL.
2. **The timer is blocked on `heartbeat_lock`.** Every lease publication holds that lock through path traversal, JSON serialization, flush, `fsync`, and atomic replace (`runtime.py:897-914`; `private_io.py:355-398`). An event/status path can own the same lock while its filesystem operation stalls. `journal_lock` contention alone cannot block the timer: the timer never acquires it (`runtime.py:4243-4269`).
3. **Lease writes repeatedly fail.** Both the writer and timer suppress `OSError` (`runtime.py:913-914,4262-4269`), leaving the prior timestamp in place. `EMFILE`/`ENFILE`, `ENOSPC`/quota, permission or read-only changes, `EIO`/stale mounts, unsafe path replacement, and directory removal can all do this. FD exhaustion can also kill earlier through the opaque `state_missing`/`heartbeat_invalid` read classifications described above, before five seconds elapse.
4. **Wall time advances abruptly.** Scheduling uses monotonic time, but the persisted value and stale comparison use `time.time()` (`runtime.py:910-911,4262-4269,4349-4350`). A forward clock correction larger than the remaining margin creates an immediately stale sample until the next timer write; a backward correction does not.
5. **Another actor regresses or replaces the heartbeat.** Restoring an old workflow directory/heartbeat, overwriting it with an old finite epoch, or continuously racing the writer can present a valid stale value. The bounded reader guarantees a trusted, coherent file; it does not guarantee that the value is current (`private_io.py:45-110`).

Long journal-silent phases, `journal_lock` contention, slow notifications, and long children are not independent stale causes at HEAD. Current process tests explicitly cover a 3.5-second journal-empty script, a long child, one failed write, one refused read, and slow gate/soft-park notifications (`tests/test_workflow_watchdog.py:202-374`).

## Recommended design and tradeoffs

The clean fix is one typed observation path, one confirmation policy, and a monotonic timer-health signal. Do not bolt more reason-specific branches onto `_run`.

1. **Use typed, strict observations and preserve I/O diagnostics.** Replace `_check`'s `exists()` plus forgiving reads with a watchdog-specific strict read that returns a small value such as `(kind, path_role, io_reason, errno, observed_monotonic)`. Distinguish confirmed `ENOENT` from `unreadable`, malformed/tampered, terminal, and stale. Walk the preserved exception cause to capture numeric errno without persisting raw exception text. Emit the structured fields on the first degraded sample and in `workflow_watchdog_fired`; rate-limit repeated samples. This combines option (b) with the classification needed to stop treating fd pressure as deletion. Durability-per-complexity: **highest**.
2. **Apply one confirmation state machine to every cancel-capable observation.** `terminal` remains an immediate clean stop. A healthy or exempt-paused observation resets the state. Every other cancel reason must survive a fresh read after at least one heartbeat cadence, not merely the current 50 ms prompt retry; then record and cancel. Count consecutive unhealthy observations even if their diagnostic subtype changes, but preserve the first and final subtype. This is option (a). It adds at most one second to deletion response at the default cadence and closes the suspension/resume and single-stale races. Durability-per-complexity: **very high**, but it is mitigation rather than root-cause removal.
3. **Harden the lease itself.** Make the timer the sole routine heartbeat writer so event paths cannot hold its lock; publish an immediate initial lease, then one per cadence. Track `last_attempt_monotonic`, `last_success_monotonic`, and the last write errno in memory. Use monotonic age inside this same process, while retaining wall-clock fields in the file for external tools. If the disk value is stale but the timer-attempt signal is current, classify it as heartbeat persistence degradation and do not call it supervisor death; record the write error and keep retrying. If the timer signal is also stale across the confirmation window, cancel. This is option (c) and is the strongest root-cause fix, but it is a moderate refactor rather than a two-line change.
4. **Raise the built-in default from 5 to 15 seconds only as defense in depth.** Fifteen missed one-second publications still meets the original bounded-idle requirement (`docs/issues/2026-08-26-run-lifecycle-cleanup.md:37-45`) and absorbs common host pauses. It does not repair opaque reads, wall-clock semantics, or a permanently blocked writer. This is option (d): cheap, but low durability by itself.
5. **Do not add `pid alive + journal mtime` to this in-process watchdog.** Its own execution already proves the supervisor PID exists and holds the workflow lock; that signal is tautological here. Journal mtime is intentionally idle during long valid work, so requiring it would restore the bug that `dlg-a2w` removed. A PID/lock check is useful to an external reaper, not as corroboration inside `_SupervisorWatchdog`. Option (e) has poor durability-per-complexity in this location. The timer's in-memory monotonic attempt is the useful independent signal.

The recommended implementation is items 1 through 3, with item 4 in the same release as margin. The timeout delivery path interacts directly with `dlg-adl`: pinned supervisors use `pin.config`, not the current resolved config (`src/delegate_agent/workflows/commands.py:75-89`), and the pin environment points `DELEGATE_CONFIG` at the frozen snapshot (`src/delegate_agent/workflow_pinning.py:92-103`). Until `dlg-adl` lands, a live config edit cannot reliably deliver a new timeout to an existing workflow. A code default also cannot change an already pinned old runtime. Do not present the knob as an operational mitigation without a resume-time effective-value report or live safety-config overlay.

## Test plan

1. **Generic confirmation unit table.** Add sequences for `heartbeat_stale -> healthy` (no fire), two stale observations separated by one fake heartbeat cadence (one fire), mixed unhealthy subtypes (one fire with first/final diagnostics), terminal (stop without fire), and paused exemptions (no fire). Use a fake monotonic clock and no sleeps. Mutation-check separately by restoring the stale fast path, changing the threshold to three, resetting on subtype changes, and treating terminal as cancel-capable; each mutation must make its matching row fail.
2. **Strict error classification.** Inject `ENOENT`, `EMFILE`, `EIO`, invalid JSON, a symlink, and a hard link at the status and heartbeat roles. Assert `ENOENT` alone maps to confirmed missing; `EMFILE` retains `io_reason=unreadable` and `errno=24`; trust failures stay fail-closed; no case silently becomes `None`. Assert the first degraded event and final fire event carry path role, reason, and errno. Mutation-check by routing through `read_json_object_or_none`, mapping every `OSError` to missing, and deleting each diagnostic field in turn.
3. **Lease mechanics.** With fake clocks, jump wall time forward while monotonic time advances normally and assert no stale fire; hold `journal_lock` for more than two stale windows and assert timer success advances; inject one failed write and assert recovery; inject persistent `EMFILE` and assert a fresh timer-attempt signal reports persistence degradation rather than supervisor death. Mutation-check by comparing wall time again, making the timer acquire `journal_lock`, suppressing the captured write error, and treating disk-stale plus timer-current as fatal.
4. **Process regression.** Launch with a 1-second test window, `SIGSTOP` the supervisor for longer than the window, `SIGCONT` it, and assert it renews before confirmed cancellation. Keep the real deletion and frozen-heartbeat cases, but assert their structured fire reason and diagnostics. Mutation-check the stop/resume assertion by restoring single-sample stale cancellation, and the destructive cases by disabling cancellation.
5. **Config delivery.** Under `dlg-adl`'s chosen contract, create a pinned workflow, change the live safety timeout, resume, and assert the supervisor reports the effective value and source. Mutation-check by restoring `launch_config = pin.config` for the safety field; the test must fail. Also pin the 15-second built-in fallback and explicit env/config precedence in `_workflow_watchdog_stale_seconds` (`runtime.py:4231-4240`).
